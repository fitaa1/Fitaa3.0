# Fitaa Creative (fitaacreative.com)

The agency site for Fitaa Creative, based in Accra, working with businesses in Ghana, the UK and beyond. React + Vite single-page site, hosted on Vercel (project name `fitaadigital`, which serves fitaacreative.com; www and fitaacreative.vercel.app 301 to it). Standalone pages live as plain HTML in `public/`: `/fully-booked`, `/demo/ridge-house`, `/demo/studio`, `/demo/car-rental`, `/demo/clinic`, `/demo/restaurant`. Privacy, terms and the 404 are written at build time by `scripts/static-pages.mjs`.

This site is the template for every site Fitaa builds. `SITE_STANDARD.md` is the standard they all meet: when this site improves, update it in the same pull request.

Git workflow: branch + pull request for every change, never push to `main`. Nigel approves every merge.

## Run, check, deploy, roll back

- `npm ci`, then `npm run typecheck`, `npm run build` and `npm test` before every push. `npm test` fakes Vercel's country header against `middleware.ts` and checks every built copy's prices, WhatsApp number and structured data (run it after the build).
- `npm run check:pages` after the build, before every push, and on every pull request through `.github/workflows/ci.yml`. It opens every built page at 390, 820 and 1440 px in light and dark and fails on sideways scroll, a console error, an image without alt text, a tap target under 44 px, a phone menu that does not open fully and a first load over 350 KB. Fix the page when it fails, never the limit. `SHOTS=1 npm run check:pages` saves every screenshot into `shots/` to look at.
- Look at changed pages at 390, 820 and 1440 px (Playwright or a headless browser). `vite preview` does not apply `vercel.json` rewrites, so open `/fully-booked/index.html` locally, not `/fully-booked`.
- Deploy: merging to `main` deploys to production on Vercel. Each pull request gets a Vercel preview.
- Roll back in under two minutes: Vercel, project `fitaadigital`, Deployments, pick the last good production deploy, menu, **Instant Rollback** (or Promote to Production).

## Where things live

- Every word, number, link and contact detail: `src/config/site.ts`. Do not scatter contact details elsewhere.
- Prices: `src/config/pricing.json` only, once per currency (GHS, GBP, USD), each written out in full. The build writes them into the home page, Fully Booked (every `data-price` element), the structured data and `llms.txt`.
- Prices and WhatsApp by country: `middleware.ts` reads Vercel's `x-vercel-ip-country` and serves one of six built copies of each page (`dist/_r/<currency>-<line>/`, written by `scripts/prerender.mjs` and `scripts/regional-pages.mjs`). Ghana gets GHS, the UK gets GBP and the UK WhatsApp number, everyone else USD; crawlers always get USD; the only control is three small dimmed flags in the footer (home and Fully Booked), a fail-safe for a wrong guess that sets cookie `fitaa_cur`; never put a currency switch next to the prices (Nigel, 6 Nov). Flag drawings: `src/config/flags.json`. The UK number is the Vercel variable `UK_WHATSAPP` (Production only), read at build time; without it UK visitors get the Ghana number. A new page with prices or WhatsApp needs a line in `PAGES` in `middleware.ts` and in `scripts/regional-pages.mjs`.
- Share cards: `node scripts/share-cards.mjs` after a build rebuilds every 1200 × 630 card and renames it (change `CARD` in the script).
- Analytics: `public/fitaa-analytics.js` (GA4 `G-D62TL0T2VD`, events whatsapp_click, booking_request, call_click, email_click, demo_open, niche_switch, currency_switch, outbound_click, enquiry_submit; each carries the currency on screen). It only switches on for the live hosts listed in the file.
- Contact form: Formspree (`formspreeId` in `site.ts`). Messages arrive in Gmail from formspree.io, usually in the Updates tab.
- Headers and redirects: `vercel.json`.

## Content rules

British spelling, plain English, no em dashes in copy (the "—CREATIVE—" wordmark is part of the logo lockup and stays). Do not invent prices, numbers, awards or guarantees; every figure on the site needs a source Nigel has confirmed.

Straight to the point (Nigel, 4 Nov 2026): every package card on /fully-booked has its own link (`#get-found`, `#get-chosen`, `#stay-booked`) and every niche has its own demo, so a lead is sent to the exact thing they asked for, never the general page. The site's own package cards are the exception: their "Learn more" opens the whole of /fully-booked, because the open card already shows that package (Nigel, 7 Nov). Keep those ids when editing the page, and give each new demo its own tab, card and `?demo=` value. Get Chosen is the website alone: never list the Get Found items inside it.

## Known issues and guards

Found in the 22 Oct 2026 audit. Each line is a mistake that happened once, and the guard that stops it repeating.

- **Pushing and the stop hook:** Claude's clones are single-branch (`git clone --depth 1`), so Git only tracks `main` and `git push -u` cannot record a new branch. The session's stop hook then reports "unpushed commits, no remote branch" even though the branch is on GitHub. Before acting on it, check with `git ls-remote origin <branch>`. Fix once per clone: `git config --add remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'`, then `git fetch --depth=1 origin <branch>` and `git branch --set-upstream-to=origin/<branch>`. The hook lives in the Claude workspace, not in this repo.
- **Opening a pull request:** GitHub's GraphQL API is blocked in Claude's workspace, so `gh pr create` fails with 403. Use the REST route: write `{"title","head","base","body"}` to a file and run `gh api repos/fitaa1/<repo>/pulls --input pr.json`.
- **Host environment variables:** a variable reaches the site only from the next deploy. Add variables first, then trigger a deploy. On Netlify, a variable marked secret cannot use "same value for all contexts": the same value must be typed into each deploy context. Names only in docs and chats, never values.
- **Redirect hosts:** check every host name against the real project list (Cloudflare Workers: `fitaa-global` serves fitaaglobal.com, `fitaa-homes` serves fitaahomes.com; Vercel: `fitaadigital` serves fitaacreative.com; old Netlify projects `fitaaglobal` and `fitaahomes` only redirect their netlify.app addresses) before writing a redirect. A redirect once pointed at `fitaa-homes.netlify.app`, which does not exist.
- **Test scripts:** `node --test tests/` treats the folder as a file on Node 22 and fails. Use a glob such as `tests/*.test.mjs`.
- **Fail safe, never fail free:** when data cannot be read (a calendar, saved dates, a form service), the page must say so and send the visitor to WhatsApp. It must never show free dates, a green "live" tick or a success message it cannot back up.
- **Claude's workspace network:** checked 4 Nov 2026, every Fitaa host loads from the workspace (fitaacreative.com, fitaaglobal.com, fitaahomes.com, airportgrande.com). If a host is ever refused, say so in the report and confirm the live page another way before stating anything about it.
- **Google Docs edits:** an `insertText` needs a `location` or `endOfSegmentLocation`. Read the doc back after every edit before calling it done.
- **Claims:** a "done", "live" or "verified" line in a PR, doc or the Daily Log needs a real check behind it (status code, screenshot, test run). Otherwise write UNVERIFIED and why. Report what a source says and label Claude's own reading as a reading: on 11 Nov Claude read the Daily Log and told the next model which fault it "has to" trace, as if that reading were proven.
- **Contact form (Creative):** it used to show "Message Received" when no Formspree ID was set, which would silently drop every lead. It now shows the error state with the email address. Keep it that way.
- **Fonts and analytics:** Google Fonts load without blocking the first paint on every page (`index.html` and each page in `public/`). Google Analytics loads on the visitor's first tap, scroll or key press, or after 4 seconds (`public/fitaa-analytics.js`, Nigel's choice: skimmers under 4 s aren't counted, Vercel Analytics still counts them). Never turn either back into an early or blocking load: the fonts cost about 1 s of first paint, and GA locks a slow phone for about 0.8 s.
- **Splash:** one 0.5 s pulse of the logo on the first visit of a session, then the logo opens into the page (`index.html`). Nigel chose 0.5 s. It starts when the logo has loaded, and only first visits download `logo-224.webp`.
- **Preview photos:** every photo on a lead preview lives in `public/preview/<page>-img/` as WebP, at most 1200 px on the long side. Never hotlink Airbnb, Booking.com or Trip.com images: their links change and the preview breaks. `scripts/localise-preview-images.py` copies hotlinked photos in (set `PAGES`; run it where the network can reach those sites, such as the Codespace), then convert them to WebP.
- **Questions on /fully-booked:** the FAQPage data in the page head is built from the visible questions. Change both together, or Google and AI answers quote the old wording.
- **Portfolio images:** each needs `name.webp` (1440 px), `name-1080.webp` and `name-720.webp` in `public/work/`, so phones never download the large file.
- **Second GA destination:** every event on this site also reaches a second GA4 property, `G-G4NQ36GKW4`. It is not in the code, so it comes from the Google tag settings in Google Analytics (Admin, Data streams, Configure tag settings, Manage Google tag). Nigel decides whether to keep it.
- **Credit and attribution (Nigel, 11 Nov 2026):** Fitaa OS and every Fitaa site are Nigel's, built under his direction and correction and paid for by him. Claude appended "Generated with Claude Code" and co-author lines to that work and wrote "we" about building it. Guard: footers read "Generated by Fitaa" and commits carry no co-author lines (`.claude/settings.json` and `.qwen/settings.json` turn them off, keep both files). Logs and pull requests name Nigel's decisions as his and Claude's mistakes as Claude's, never "we" and never "the system" for a mistake Claude made.
- **The whole request, traced through (Nigel, 11 Nov 2026):** Claude narrowed a whole-system audit to some repos and left the lead pipeline out, and more than once fixed one thing while breaking or missing another. Guard: do everything that was asked, across every part it covers, and before calling a change done trace it through every file, record, page and scheduled task that reads it. When a check fails, fix the cause in the same piece of work. Never loosen the check, never only remind Nigel, never call a protective step optional, and never put Claude's process (a log, a merge) ahead of the work being right.
- **Plain, direct and lean (Nigel, 4 and 11 Nov 2026):** pitches to leads were wishy-washy and rules were stacked instead of condensed. Guard: every message and page that sells says what was built, what it does for this person, the price where Nigel's rules allow one, and the link to the exact thing. Everything written for Nigel uses plain words with no em dashes, semicolons, colons in his messages, jargon or status codes. A correction is folded into the rule it changes, everywhere that rule is read, the same day. No extra files, workaround docs or second copies.
